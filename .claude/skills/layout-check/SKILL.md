## Что делает

Открывает страницы `apps/web` в двух вьюпортах (десктоп и мобайл), снимает скриншоты, ищет
типовые дефекты адаптива и выдаёт отчёт. Ничего не правит — только диагностирует.

Вызывается вручную (`/layout-check`) и подхватывается сам после правок вёрстки в `apps/web`
(изменения в `*.tsx`, `globals.css`, классах Tailwind).

## Аргументы

```
/layout-check [<url|путь>]
```

| Аргумент    | Обязателен | Смысл                                                               |
| ----------- | ---------- | ------------------------------------------------------------------- |
| `url\|путь` | нет        | одна страница: `/login`, `http://localhost:3000/login`; пусто — все |

Путь без хоста достраивается до `http://localhost:3000`. Если в аргументе внешний хост —
проверять его как есть, шаги про dev-сервер и авторизацию пропустить.

## Страницы приложения

Роутов немного, они перечисляются явно — не сканировать `app/` каждый раз, но если в
`apps/web/src/app` появился новый `page.tsx`, добавить его сюда. Файлы в `app/api/` — это
route handlers BFF, а не страницы; их не проверять.

| Путь        | Доступ       | Что смотреть                            |
| ----------- | ------------ | --------------------------------------- |
| `/login`    | только гость | форма, центрирование карточки           |
| `/register` | только гость | форма, длинные тексты ошибок            |
| `/`         | нужна сессия | список транзакций, категории, пагинация |

Демо-аккаунт для входа — **`demo@example.com` / `demo1234`** (сид из
`packages/db/prisma/seed.ts`). Если сида в базе нет — сказать об этом и предложить
`npm run db:seed`, а не регистрировать новый аккаунт.

## Порядок обхода

Гарды взаимно исключающие: `/` под гостем редиректит на `/login`
(`apps/web/src/app/page.tsx`), а `/login` и `/register` под сессией — на `/`
(`apps/web/src/app/(auth)/login/page.tsx`). Одним проходом все страницы не снять, поэтому
фазы такие:

1. **Гость:** `/login`, `/register` — оба вьюпорта. До логина, не после.
2. **Логин** демо-аккаунтом — один раз за прогон: кука живёт в контексте браузера,
   `browser_resize` её не сбрасывает, повторно логиниться под второй вьюпорт не нужно.
3. **Сессия:** `/` — оба вьюпорта.

Логин: `browser_navigate` на `/login` → `browser_fill_form` (email, пароль) → `browser_click`
по кнопке отправки → `browser_wait_for` до контента главной. Если после сабмита остались на
`/login` — сначала смотреть текст ошибки и ответ `/api/auth/login`, а не вёрстку.

Если после навигации оказались не на том URL, который запрашивали, — сработал гард, состояние
сессии не совпадает с фазой. Это не дефект вёрстки, страницу переснять в правильной фазе.

Аргументом передана одна страница — выполняется только её фаза.

## Вьюпорты

| Профиль | Размер     | Чему соответствует                     |
| ------- | ---------- | -------------------------------------- |
| desktop | 1440 × 900 | выше `lg` (1024) Tailwind              |
| mobile  | 390 × 844  | iPhone 14/15, ниже `sm` (640) Tailwind |

Третий размер добавлять только если пользователь попросил или дефект явно живёт на границе
`md` (768) — тогда добить 768 × 1024 точечно, а не гонять все страницы.

## Предусловия

1. Dev-сервер на `:3000` и API на `:3001` должны быть подняты — главная без API отрисует
   пустой список, и это будет ложный дефект.

   ```bash
   netstat -ano | grep ':3000 ' | grep LISTENING
   netstat -ano | grep ':3001 ' | grep LISTENING
   curl -s -o /dev/null -w "%{http_code}" http://localhost:3001/api/auth/me   # 401 = API жив
   ```

   `/auth/me` под гардом, поэтому без куки отвечает `401` — этого достаточно, чтобы убедиться,
   что порт держит именно API, а не посторонний процесс. `000` — соединения нет.

2. Если не подняты — запустить `npm run dev` в фоне и дождаться готовности. Порт занят
   чужим процессом — не убивать его молча, сообщить пользователю (см. `apps/web/CLAUDE.md`,
   раздел про EADDRINUSE).

## Алгоритм

Для каждой страницы фазы, для каждого вьюпорта:

1. `browser_resize` → нужный размер. Ресайз **до** навигации, иначе первый рендер уйдёт в
   другую ширину и медиазапросы отработают не те.
2. `browser_navigate` → URL.
3. `browser_wait_for` — дождаться характерного текста страницы, если контент подгружается.
4. `browser_evaluate` — переполнение по горизонтали и его виновники:

   ```js
   () => {
     const doc = document.documentElement;
     const overflow = doc.scrollWidth - doc.clientWidth;
     if (overflow <= 1) return { overflow: 0, guilty: [] };
     // потомки контейнера со своим горизонтальным скроллом торчат за вьюпорт
     // по getBoundingClientRect, хотя визуально обрезаны — это не дефект
     const inScroller = (el) => {
       for (let p = el.parentElement; p; p = p.parentElement) {
         const ox = getComputedStyle(p).overflowX;
         if (ox === "auto" || ox === "scroll") return true;
       }
       return false;
     };
     const over = [...document.querySelectorAll("body *")].filter((el) => {
       const r = el.getBoundingClientRect();
       return r.width > 0 && r.right > doc.clientWidth + 1 && !inScroller(el);
     });
     // оставляем листья: родитель широкий из-за ребёнка, чинить нужно ребёнка
     const guilty = over
       .filter((el) => !over.some((o) => o !== el && el.contains(o)))
       .slice(0, 5)
       .map((el) => ({
         tag: el.tagName.toLowerCase(),
         cls: (el.getAttribute("class") ?? "").slice(0, 80),
         right: Math.round(el.getBoundingClientRect().right),
       }));
     return { overflow, guilty };
   };
   ```

5. Только на мобайле — `browser_evaluate` по тач-таргетам (глазами 44 px не измерить):

   ```js
   () =>
     [...document.querySelectorAll("a, button, [role=button], input, select")]
       .map((el) => ({ el, r: el.getBoundingClientRect() }))
       .filter(({ r }) => r.width > 0 && r.height > 0 && (r.width < 44 || r.height < 44))
       .slice(0, 10)
       .map(({ el, r }) => ({
         tag: el.tagName.toLowerCase(),
         text: (el.textContent ?? "").trim().slice(0, 30),
         size: `${Math.round(r.width)}×${Math.round(r.height)}`,
       }));
   ```

6. `browser_take_screenshot` с `fullPage: true` и именем `<страница>-<вьюпорт>.png`
   (`login-mobile.png`). **Только имя файла, без пути** — на абсолютный путь MCP создаёт
   файл с двоеточиями в имени внутри `.playwright-mcp/`.
7. Прочитать скриншот через `Read` и осмотреть глазами — половина дефектов вёрстки не
   ловится скриптом. Но горизонтальный скролл по скриншоту не виден: `fullPage` снимает
   холст по размеру контента, и переполнение выглядит как нормальная широкая страница.
   Судить о нём только по числу из шага 4.
8. `browser_console_messages` — собрать ошибки (hydration mismatch, 404 на шрифты/картинки).

В конце — `browser_close`.

## Что считать дефектом

- **Горизонтальный скролл на мобайле** — `overflow > 0` из шага 4. Почти всегда
  фиксированная ширина, `min-w`, или таблица без обёртки со `overflow-x`.
- **Обрезанный или наезжающий текст** — длинные суммы и названия категорий в узкой колонке.
- **Элементы, уехавшие за вьюпорт** — кнопки, модалки, выпадающие списки.
- **Тач-таргеты меньше 44 × 44 px** на мобайле — по списку из шага 5. Элементы с большим
  паддингом у родителя-ссылки дефектом не считать, если кликабельна вся строка.
- **Пропавшая навигация** — то, что на десктопе в сайдбаре, а на мобайле нигде.
- **Ошибки консоли**, влияющие на отрисовку: hydration mismatch, битые ассеты.
- **Пустые блоки** там, где ожидались данные — сначала `browser_network_requests` и проверить,
  что запросы к API не легли (401/500/CORS), и только потом записывать в дефекты вёрстки.

Мелкие расхождения в пикселях, антиалиасинг и отличия шрифтового рендера дефектами не
считать.

Коротко и по делу, без пересказа алгоритма:

```markdown
| Страница | Desktop | Mobile     |
| -------- | ------- | ---------- |

| /        | ок      | 2 проблемы |

### Проблемы

1. **`/` mobile — горизонтальный скролл 48px.** Виновник: `div.transactions-table`
   (`apps/web/src/widgets/.../Table.tsx:24`) — фиксированная `min-w-[600px]` без
   обёртки `overflow-x-auto`.

Скриншоты: `.playwright-mcp/login-mobile.png`, ...
```

Для каждой проблемы: страница, вьюпорт, что видно, файл и строка причины, предлагаемая
правка одной фразой. Скриншоты перечислить путями от корня репозитория — пользователь
откроет сам.

Если всё чисто — так и написать одной строкой, не расписывать проверенное.

## Запрещено

- **Не править код.** Скилл диагностирует; правки — отдельной задачей после подтверждения
  пользователя.
- Не коммитить скриншоты: `.playwright-mcp/` — мусорная папка, в репозиторий не идёт.
- Не убивать процессы на `:3000`/`:3001` без спроса.
- Не регистрировать новые аккаунты для входа — только демо-аккаунт из сида.
- Не гонять все страницы, если пользователь передал одну.
