# API

Все эндпоинты NestJS-бэкенда. Базовый URL — `http://localhost:3001/api` (глобальный префикс
`/api` задан в `main.ts`). Интерактивная версия с телами и схемами — `/api/docs`.

## Общие правила

**Авторизация.** Публичны только `POST /auth/register` и `POST /auth/login`. Остальное требует
заголовка `Authorization: Bearer <accessToken>`. Токен живёт 7 дней.

**userId не передаётся в запросе.** Он берётся из токена. Query-параметры — только фильтры;
`?userId=` не поддерживается специально, иначе можно было бы читать чужие данные.

**Деньги — строки.** `amount`, `income`, `expense`, `balance`, `total` приходят и уходят
строками вида `"1234.56"`: в БД это `Decimal(12,2)`, а JSON-число теряет копейки.

**Чужая запись = 404.** Запись другого пользователя неотличима от несуществующей.

**Ошибки.** Формат — стандартный для Nest: `{ statusCode, message, error }`. Для zod-валидации
(`auth`) в тело добавляется массив `issues` от zod.

| Код | Когда |
|---|---|
| 400 | тело/параметры не прошли валидацию, `id` не UUID, лишние поля в теле |
| 401 | токена нет, он истёк или неверен; неверный пароль; пользователь удалён |
| 404 | записи нет или она принадлежит другому пользователю |
| 409 | email занят; имя категории занято |

## Auth

### `POST /api/auth/register`

Регистрация. Публичный. Пароль хэшируется bcrypt и наружу не возвращается никогда.

Тело:

| Поле | Тип | Ограничения |
|---|---|---|
| `email` | string | формат email, уникален |
| `name` | string | 1–120 символов |
| `password` | string | 8–72 символа |

Предел в 72 символа не декоративный: bcrypt молча обрезает всё после 72 байт.

Ответ `201`:

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": "uuid", "email": "user@example.com", "name": "Иван" }
}
```

Ошибки: `400` — тело не прошло схему, `409` — email занят.

### `POST /api/auth/login`

Вход. Публичный. Отвечает `200`, а не `201`.

Тело: `email` (формат email), `password` (непустая строка). Ответ — как у регистрации.

Ошибки: `400` — тело не прошло схему, `401` — неверный email **или** пароль (ответ одинаковый
в обоих случаях, чтобы не подсказывать, какие адреса зарегистрированы).

### `GET /api/auth/me`

Профиль владельца токена. Требует Bearer.

Ответ `200`: `{ "id": "uuid", "email": "...", "name": "Иван" }` (`name` может быть `null`).

Ошибки: `401` — токена нет/он неверен либо пользователя из токена больше нет в БД.

## Transactions

Все эндпоинты требуют Bearer.

### `GET /api/transactions`

Список транзакций пользователя, сортировка по дате — сначала новые.

Query-параметры (все необязательны):

| Параметр | Тип | Ограничения | Значение |
|---|---|---|---|
| `dateFrom` | string | ISO-8601 | нижняя граница даты, включительно |
| `dateTo` | string | ISO-8601 | верхняя граница даты, включительно |
| `type` | enum | `INCOME` \| `EXPENSE` | фильтр по типу |
| `categoryId` | string | UUID | фильтр по категории |
| `page` | number | ≥ 1, дефолт 1 | номер страницы |
| `limit` | number | 1–100, дефолт 20 | размер страницы |

Ответ `200`:

```json
{
  "items": [
    {
      "id": "uuid",
      "amount": "1234.56",
      "type": "EXPENSE",
      "description": "Обед в кафе",
      "date": "2026-08-06T00:00:00.000Z",
      "category": { "id": "uuid", "name": "Продукты", "color": "#a1b2c3", "icon": null },
      "createdAt": "2026-08-06T12:34:56.789Z"
    }
  ],
  "total": 137,
  "page": 1,
  "limit": 20
}
```

`total` — количество записей по фильтру целиком, без учёта пагинации.

Ошибки: `400` — неизвестный query-параметр или неверный формат, `401`.

### `GET /api/transactions/summary`

Итоги за календарный месяц. Маршрут объявлен до `/:id`, иначе `ParseUUIDPipe` перехватил бы
слово `summary`.

Query-параметры (оба обязательны): `month` — 1–12 (январь = 1), `year` — 2000–2100.

Ответ `200`:

```json
{
  "income": "75000.00",
  "expense": "43250.10",
  "balance": "31749.90",
  "byCategory": [
    { "categoryId": "uuid", "name": "Продукты", "type": "EXPENSE", "total": "4300.00" }
  ]
}
```

`balance` = `income − expense`, может быть отрицательным. В `byCategory` по строке на пару
«категория + тип»; `name` пустой, если категорию удалили. Месяц без транзакций даёт нули и
пустой массив. Границы месяца считаются по UTC — полуинтервал `[начало месяца, начало
следующего)`.

Ошибки: `400` — `month`/`year` отсутствуют или вне диапазона, `401`.

### `GET /api/transactions/:id`

Одна транзакция. `id` — UUID.

Ответ `200` — объект транзакции (как элемент `items` выше).

Ошибки: `400` — `id` не UUID, `401`, `404`.

### `POST /api/transactions`

Создать транзакцию.

Тело:

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| `amount` | string | да | `^\d+(\.\d{1,2})?$`, например `"1234.56"` |
| `type` | enum | да | `INCOME` \| `EXPENSE` |
| `date` | string | да | ISO-8601 |
| `categoryId` | string | да | UUID, категория должна принадлежать пользователю |
| `description` | string | нет | до 500 символов |

Ответ `201` — созданная транзакция.

Ошибки: `400`, `401` (в том числе если пользователь из токена удалён), `404` — категория не
найдена или чужая.

### `PATCH /api/transactions/:id`

Частичное обновление: непереданные поля остаются как были. Тело — те же поля, что у `POST`,
все необязательные.

Ответ `200` — обновлённая транзакция.

Ошибки: `400`, `401`, `404` — транзакция не найдена/чужая либо новая категория не найдена/чужая.

### `DELETE /api/transactions/:id`

Удалить транзакцию. Ответ `204`, тело пустое.

Ошибки: `400` — `id` не UUID, `401`, `404`.

## Categories

Все эндпоинты требуют Bearer.

### `GET /api/categories`

Все категории пользователя, отсортированы по имени.

Ответ `200`:

```json
[{ "id": "uuid", "name": "Продукты", "color": "#6366f1", "icon": "shopping-cart" }]
```

Пустой массив, если категорий нет. Ошибки: `401`.

### `GET /api/categories/:id`

Одна категория. Ответ `200` — объект категории.

Ошибки: `400` — `id` не UUID, `401`, `404`.

### `POST /api/categories`

Создать категорию.

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| `name` | string | да | 1–60 символов, уникально в пределах пользователя |
| `color` | string | нет | `^#[0-9a-fA-F]{6}$`; без значения в БД дефолт `#6366f1` |
| `icon` | string | нет | до 40 символов |

Ответ `201` — созданная категория.

Ошибки: `400`, `401` (в том числе если пользователь удалён), `409` — имя занято.

### `PATCH /api/categories/:id`

Частичное обновление, все поля необязательны. Ответ `200`.

Ошибки: `400`, `401`, `404`, `409` — новое имя занято другой категорией пользователя.

### `DELETE /api/categories/:id`

Удалить категорию. Ответ `204`, тело пустое.

Каскад: вместе с категорией удаляются её транзакции (`onDelete: Cascade` в схеме).

Ошибки: `400` — `id` не UUID, `401`, `404`.

## Payments

Регулярные платежи — шаблоны повторяющихся операций (подписки, аренда, зарплата). Сам платёж
денег не двигает: фактом операции становится транзакция, которую создаёт `POST /:id/pay`.

Все эндпоинты требуют Bearer. Валидация — zod, поэтому в ответе `400` приходит массив `issues`.

### `GET /api/payments`

Список платежей пользователя, ближайшие по дате списания — первыми.

Query-параметры (все необязательны):

| Параметр | Тип | Значение |
|---|---|---|
| `isActive` | `"true"` \| `"false"` | только включённые или только выключенные |
| `categoryId` | UUID | фильтр по категории |
| `dueBefore` | ISO-8601 | платежи с датой списания не позже указанной |

Ответ `200`:

```json
[
  {
    "id": "uuid",
    "name": "Подписка на музыку",
    "amount": "299.00",
    "type": "EXPENSE",
    "period": "MONTHLY",
    "nextDueDate": "2026-09-01T00:00:00.000Z",
    "isActive": true,
    "description": null,
    "category": { "id": "uuid", "name": "Подписки", "color": "#6366f1", "icon": null },
    "createdAt": "2026-08-06T12:34:56.789Z"
  }
]
```

Ошибки: `400`, `401`.

### `GET /api/payments/upcoming`

Что спишется в ближайшие N дней. Маршрут объявлен до `/:id`, иначе `ParseUUIDPipe` перехватил бы
слово `upcoming`.

Query-параметр `days` — 1–365, по умолчанию 30.

Ответ `200`:

```json
{ "items": [], "totalIncome": "75000.00", "totalExpense": "12480.00" }
```

Берутся только активные платежи. Просроченные (дата уже прошла) в выборку попадают — их всё
равно предстоит оплатить.

Ошибки: `400` — `days` вне диапазона, `401`.

### `GET /api/payments/:id`

Один платёж. Ошибки: `400` — `id` не UUID, `401`, `404`.

### `POST /api/payments`

Создать платёж.

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| `name` | string | да | 1–60 символов |
| `amount` | string | да | `^\d+(\.\d{1,2})?$` |
| `type` | enum | да | `INCOME` \| `EXPENSE` |
| `period` | enum | да | `WEEKLY` \| `MONTHLY` \| `QUARTERLY` \| `YEARLY` |
| `nextDueDate` | string | да | ISO-8601, дата ближайшего списания |
| `categoryId` | string | да | UUID, категория должна принадлежать пользователю |
| `description` | string \| null | нет | до 500 символов |
| `isActive` | boolean | нет | по умолчанию `true` |

Ответ `201` — созданный платёж. Ошибки: `400`, `401`, `404` — категория не найдена или чужая.

### `PATCH /api/payments/:id`

Частичное обновление, все поля необязательны. Ответ `200`.

Ошибки: `400`, `401`, `404`.

### `POST /api/payments/:id/pay`

Отметить платёж оплаченным: создаёт транзакцию по его данным и сдвигает `nextDueDate` на период
вперёд. Оба действия идут в одной транзакции БД.

Ответ `201`:

```json
{ "payment": { "nextDueDate": "2026-10-01T00:00:00.000Z" }, "transaction": { "amount": "299.00" } }
```

Дата транзакции — та, на которую платёж был назначен, а не «сейчас»: платёж могли отметить с
опозданием, и в отчёт он должен попасть по плановому месяцу. Описание берётся из платежа, а если
его нет — подставляется имя платежа.

Сдвиг даты прижимается к последнему дню короткого месяца: 31 января + месяц = 28 (или 29)
февраля, а не 3 марта.

Ошибки: `400` — `id` не UUID, `401`, `404`.

### `DELETE /api/payments/:id`

Удалить платёж. Ответ `204`. Уже созданные из него транзакции остаются — они факт, а не часть
шаблона.

Ошибки: `400`, `401`, `404`.

## BFF-роуты фронтенда

Это **не** эндпоинты Nest, а Route Handlers Next.js на `http://localhost:3000`. Браузер ходит
только сюда; JWT в ответ не попадает — он кладётся в httpOnly-куку `session`.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/auth/register` | проксирует в Nest, ставит куку, отдаёт `{ user }` |
| `POST` | `/api/auth/login` | то же |
| `POST` | `/api/auth/logout` | сбрасывает куку |

Ошибки бэкенда (400/401/409) пробрасываются со статусом и `message`; фичи маппят их на поля
формы.
